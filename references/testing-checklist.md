# 测试清单（参照）

> 原版测试覆盖记录 + 重构版兼容验收清单。重构版测试设计以此为基线。

## 1. 原版自动化测试覆盖（5 套）

### 1.1 协议 v1（覆盖最重）

- 加解密往返：短文本、10 万字符长文本、复杂 Unicode（中文、Emoji、日韩文、阿拉伯文、换行/制表符）。
- 加密侧错误：空白明文、坏公钥、1024 位小公钥、缺公钥。
- **线格式断言**：JSON 恰 5 个字段、`ver = 1`、nonce 12 字节、tag 16 字节、`ek` 可解出 32 字节会话密钥。
- 解密侧错误：缺 `ver` / `ver = 0` / `ver = 2` / `ver = -1`；缺 `ek/nonce/tag/ct` 或为 null；非法 Base64；Base64 明文非 JSON；nonce 11/13/0 字节；tag 15/0 字节；空包；空 `ct`；错私钥/错密码/缺私钥/缺密码/小私钥。
- **篡改检测**：对每个字段做首字节异或，必须解密失败。
- **前向兼容**：含未知字段（如 `alg`、`future`）的包必须正常解密。
- **随机性**：同一明文两次加密，密文与 nonce 均不同。

### 1.2 密钥管理

- 生成：空密码/位数错误拒绝；四种位数的 PEM 头与位数正确；指纹 = 派生公钥指纹、32 位大写 hex、稳定、不同密钥不同。
- 导入公钥：把私钥 PEM 当公钥、垃圾输入、缺失、1024 位 → 各自对应错误码。
- 导入私钥：未加密 PKCS#8 重加密入库且派生公钥指纹一致；PKCS#1 可导入；加密私钥正确/错误密码；垃圾/1024 位/缺失/缺密码 → 对应错误码。
- 改密：新密码可用、旧密码失效、错旧密码报错、空新密码报错；派生公钥确定性。

### 1.3 密钥库

- 空目录建库 + 签名；全字段往返；重复指纹容忍保留一条；别名+指纹排序。
- `keys.json` 迁移（改名 `.migrated`）；库非空时跳过迁移；旧 `id` 列表迁移（去 id、去重）。
- 篡改/缺签名报错；信任当前库重签后恢复正常。

### 1.4 完整性

- 签名后校验通过；库不存在不报错；缺签名/篡改/签名非 Base64 报错；改库后重签（含/不含重置签名密钥）。

### 1.5 导出

- `.pub` / `.pem` 内容与命名；缺公钥/私钥报错；非法文件名净化（含中文别名）；全空白别名回退 `key`；目录不存在自动创建；中文目录与别名成功；同名覆盖。

> 实现方式备注：原版测试通过注入临时目录与独立凭据目标名实现隔离；凭据相关测试串行执行（凭据管理器是机器级共享资源，并发会瞬时错误）。

## 2. 重构版兼容验收清单（必须全绿）

1. 可解密原版加密的 Base64-JSON 密文包（含含未知字段的包）。
2. 原版可解密重构版加密的密文包（双向互操作）。
3. 可读取原版 `keys.db` 三种形态：新结构、旧 `id` 列表结构、`keys.json` 遗留。
4. 可导入原版导出的 `.pub` / `.pem`（含中文别名文件）。
5. 指纹算法与原版逐字符一致（SHA256(SPKI) 前 16 字节 → 32 位大写 hex）。
6. 可解析原版生成的加密私钥 PEM（PBES2 = PBKDF2-SHA256 ×600000 + AES-256-CBC）；原版可解析重构版生成的同参数 PEM。
7. 已记住密码的按指纹索引在迁移后仍可用（若保留凭据管理器方案）。

## 3. 测试向量建议

- 在原版上生成一组固定输入的密文包与密钥文件（含中文/Emoji 明文），作为重构版回归向量；含私钥材料的向量只放本地测试目录，不入仓库。
- 保留等价的复杂字符样例文件（原版 `ExampleMessage.txt` 的字符集）：中文、Emoji（😄🚀🔑）、日文、货币（¥8,888.88）、符号（© ™ ✓ → ←）、换行与制表符。

## 4. UI 手动清单（自动化之外）

- 深浅色主题下全部页面与对话框。
- 语言切换重启生效；`auto` 跟随系统。
- 长耗时操作（8192 位密钥生成、600k 迭代解锁）界面不冻结、有进度反馈。
- 剪贴板粘贴/复制中文字符；导出中文别名文件并在资源管理器中定位。
- 完整性失败弹窗两条路径（退出应用 / 忽略并重新签名）。
- 单实例：二次启动唤醒已有窗口。
