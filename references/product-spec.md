# 产品规格与承诺

> 原版产品定位、使用流程与对外承诺。重构版必须继承；红线不得突破。

## 1. 定位

面向 Windows 桌面端的**本地**公钥消息加密工具：用接收方公钥加密消息，接收方用自己的私钥解密密文包。全程本地完成，无服务器、无账号。

## 2. 产品红线

1. **不是即时通讯工具**：不发送消息、不暗示实时聊天；密文包由用户自行经任意渠道传递。
2. **不兼容、不命名 PGP/GPG**：自定义格式；第三方可按公开协议文档实现互通。
3. **无 PKI/CA**：公钥由用户线下自行交换，通过指纹人工核对防调包。
4. **不支持文件加密**：当前专注文本消息；文件加密仅有未实现的方向稿（见 §6），不得承诺。
5. 安全边界如实告知：无前向安全（静态私钥泄漏可解历史密文）、无密钥过期/吊销。
6. 许可证：GNU AGPL v3.0。

## 3. 使用流程（官方快速开始 4 步）

1. **接收方生成密钥对**：「我的私钥」页 →「生成密钥」→ 输入并确认私钥密码 → 列表出现新密钥（别名、指纹、密钥类型）。注：私钥密码是使用私钥的凭证，软件不存储密码（除非勾选「记住密码」）。
2. **交换公钥**：接收方复制/导出公钥发给对方；发送方在「接收方公钥」页导入（粘贴文本或从文件）并设置别名。注：建议经可信渠道核对指纹，防止公钥被调包。
3. **发送方加密**：「消息加密」页选接收方公钥 → 输入明文 →「加密」生成密文包 → 经任意渠道发送。
4. **接收方解密**：「消息解密」页选自己的私钥 → 粘贴密文包 →「解密」→ 输入私钥密码 → 得到明文。

## 4. FAQ（对外口径，共 12 条）

重构版官网/帮助需保持一致口径：

1. **是即时通讯软件吗？** 不是。无服务器、不发送消息，只在本地做明文↔密文包转换，密文包由用户自行传递。
2. **与 PGP/GPG 兼容吗？** 不兼容。自定义格式（Base64 包裹的 JSON）；第三方按 protocol-v1 文档可实现互通。
3. **忘记私钥密码怎么办？** 私钥以密码加密存本地，密码不存储（除非主动记住）。忘记即无法解密且不可找回，只能重新生成密钥对并让对方改用新公钥。
4. **密钥和密码保存在哪里？** 密钥在应用本地数据目录的密钥库（SQLite + 完整性签名）；勾选「记住密码」后密码存 Windows 凭据管理器，按私钥指纹区分。全部仅存本机。
5. **启动时提示密钥库完整性校验失败？** 常见原因：手动编辑数据库、第三方同步/备份工具覆盖、磁盘异常。可选「退出应用」或「忽略并重新签名」（危险操作，会重置签名密钥），忽略后应核对密钥列表。
6. **如何确认对方公钥没被调包？** 在密钥页查看指纹，经可信渠道与对方核对；指纹由公钥内容计算，任何改动都会变化。
7. **同样明文每次密文不同？** 正常。每次加密随机生成新会话密钥与随机数。
8. **为什么解密失败？** 密文包复制不完整/被修改（校验必失败，不输出任何内容）；选错私钥；私钥密码错误。
9. **删除私钥后还能解密旧消息吗？** 不能，删除不可恢复。建议删除前导出私钥备份（导出的仍是加密 PEM，需密码）。
10. **如何迁移到新电脑？** 旧机导出私钥（`.pem`）新机导入；公钥可导出（`.pub`）重新分享。
11. **支持文件加密吗？** 暂不支持，当前专注文本消息。
12. **支持哪些系统？** Windows 10（版本 17763）及以上，x86/x64/ARM64，Microsoft Store 分发。

> 注：第 4、12 条含原版实现细节与分发方式；重构版如有变化，需同步修订官网 FAQ。

## 5. 协议 v2 方向（未定稿，不承诺）

来自原版设计稿（原项目 `docs/protocol-v2.md`，未发布承诺）：

- `ver = 2`，新增 `alg` 字段（`rsa` / `x25519`）与发送方临时公钥 `epk`。
- X25519 共享秘密 + HKDF-SHA256 派生 AES-256-GCM 会话密钥；nonce/tag 长度同 v1。
- HKDF 的 salt / info / AAD 尚未定稿。
- 重构版架构应不阻碍 v2（`ver` 校验、未知字段忽略、稳定错误码已为此铺路），但**不实现、不预告**。
